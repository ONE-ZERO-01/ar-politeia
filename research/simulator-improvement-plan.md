# AR-Politeia 模拟器改进与重新验证计划

日期：2026-09-07。状态：详细实施方案，尚未执行。

本计划基于活动源码 `research/src/experiments/politeia/`、实验驱动 `run_landscape_study.py`、Cycle 3 参数锁与已提交校准结果的静态审查。目标是先使模拟器的微观规则、数值实现和证据判定一致，再重新验证景观效应。不是增加更多社会模块，也不是保证得到显著结果。

本文不覆盖或修改现有 `plan.json`、`parameter_lock.json`、`findings.json` 和服务器任务状态。旧参数锁明确要求确认性执行后的科学修改进入新版本和新研究周期，因此建议以 Cycle 4 承接实施。本文中的实验 ID 和新增文件名均为拟定名称；预算表不是执行授权。

## 1. 完成标准与研究边界

完成不以“所有 Gate 显示绿色”为标准，而以以下条件同时满足为标准：

1. 明确写出实际模拟的过程，包括交换边界、生产与衰减、温控、随机来源、粒子邻域和更新顺序。
2. 已确认的实现错误有最小复现和回归检查；高风险模型选择有对照实验。
3. 任何“稳态”结论都通过对应观测量的稳态检查；不以一个指标稳定替代整套分布稳定。
4. 在非退化景观上建立数值误差界，并与科学上关心的最小效应分别报告。
5. 冻结代码、判据和参数后，在独立种子与保留景观上重新验证。
6. 能给出清楚的 supported / contradicted / inconclusive 结论，包括允许主张被否定。

继续保留当前研究的边界：只研究合成景观中的生成机制，不解释中国统一、欧洲分裂、国家涌现或现实制度。模块数量不是模型可信度的替代指标。

## 3. WP0：冻结旧证据并明确因果结构

### 3.1 保存可追溯基线

记录当前源码 commit、工作区差异、参数锁哈希、E0/E1/E2/E3 结果版本和分析脚本版本。检查旧输出的最小粒子财富是否来自足够精度的记录：E0 已记录 minimum_wealth=0，但还需区分真实零值和输出舍入。

不覆盖旧结果，不把新版本生成的结果填入旧实验目录。建立 `research/simulator-remediation-status.md`，记录每个问题的证据、修改 commit、验证实验、完成状态和残余限制。

### 3.2 写出当前因果图

当前受控实验的核心关系为：

```
景观 → 地形力 → 位置 → 邻接交易 → 财富
景观 + 位置 + 技术初值 → 生产 → 财富
财富 → 衰减
```

在出生、死亡、承载力等关闭且运动方程不读财富时，没有“财富 → 位置”的反馈。社会作用强度为零时，空间聚集主要由外场运动产生；额外全局温控仍可能引入运动粒子间的共同干预，因此不直接声称严格独立粒子。

把 E2 的空间零效应改解释为结构隔离检查。财富指标上的生产与交互效应仍可作为有内容的问题，但必须把生产因子准确称为“生产—衰减组合通道”。不为获得非零效应而临时添加财富驱动迁移。

### 3.3 旧结论处置

| 旧证据 | 暂定用途 | 重新成为确认性证据的条件 |
|---|---|---|
| C1 数值校准 | 旧核在测试条件下的守恒/非负记录 | 新边界、非退化景观、步长及随机性验证通过 |
| C2 景观差异 | 旧模型有限时间内的已观察效应 | 新核心上独立重跑，全部相应稳态检查通过 |
| C3 通道归因 | 空间隔离检查及财富通道探索 | 明确因果结构和组合因子后重新设计 |
| C4 规模稳健性 | 旧版本的规模/分辨率敏感性记录 | 新基线验证后再开展确认性规模实验 |

本计划不据本地 `state.md` 判断 E3 此刻是否仍运行。执行 WP0 时先只读核实服务器状态；不自动停止已有授权任务，也不追加同版本的大规模扫描。旧任务完成可保留为旧版本证据。

验收：每项主张都能定位到模型版本、分析版本及适用边界；运行态保持独立。

## 4. WP1：交换核边界与微观规则

### 4.1 首先解决零财富跳过

涉及 `src/interaction/resource_exchange.cpp`。当前 `wi <= 0 || wj <= 0` 的跳过条件应被明确的边界政策替代。

推荐候选：允许一方为零、总财富大于零的交易进入计算；总财富为零时无操作；负财富输入作为错误或单独已声明状态处理，不能用静默跳过掩盖。检查 ability 分母和 epsilon 非法值。每对更新由共享 total 构造两端财富，保留零和。

只删掉跳过条件并不保证恢复。按当前参数 k=1、eta=0.5，一方为零且另一方能力为正时 D=-1，边界漂移 k/2-eta=0；是否离开边界还依赖噪声及边界规则。必须明确要求的是“允许回流”还是“确定性必然回流”，不能把两者混为一谈。

### 4.2 冻结边界过程

顺序评估两个方案，不同时展开多个研究方向：

1. 先保留份额截断，修正零财富跳过，并记录越界与截断频率，测量边界驻留随 dt 的变化。
2. 若边界质量不随步长稳定或长期吸收仍主导，再设计保持区间的离散过程。此时必须重新定义目标过程与参数解释，不能把换核称为纯实现修复。

不可给所有穷人加 epsilon 财富：这会制造财富并改变模型。不能只通过调小噪声把问题隐藏。

### 4.3 最小验证矩阵

拟定 `V1-EXCHANGE-BOUNDARY-C4`：

| 场景 | 检查 |
|---|---|
| (0, W)、(W, 0)、(0, 0) | 边界行为与交换标签对称性 |
| 极不均匀正财富 | 截断、恢复和数值误差 |
| 等财富且等 epsilon | 若继续保留 equal-state 吸收，必须精确验证 |
| 等财富但不同 epsilon | 不应误归类为 equal-state；检查能力差漂移 |
| 多粒子密集图 | 连续交易后守恒与非负 |
| 生产开/关 | 区分交易恢复与生产救济 |

输出零财富比例、近零财富比例、活跃交易比例、边界进入/退出次数、驻留时间、Gini、方差、分位数和 top-share。近零阈值按平均财富归一化并提前冻结。

验收：守恒相对误差沿用 1e-8 作为候选上界，同时报告随步数增长的误差；无非法负值；边界行为符合声明；不能仅以非负和 Gini 稳定宣布通过。长期无法证明非平凡稳态时，报告有限时间结果或 inconclusive。

## 5. WP2：随机数、标签与更新顺序

### 5.1 独立随机子流

将随机数键设计为 `(base_seed, stream_id, stable_gid_low, stable_gid_high, step, draw_id)`。运动、交换、人口事件分别用不同 stream；seed 不再只影响初值和运动。

配对景观实验可以有意使用共同随机数，但要声明配对策略。不同 replicate_seed 必须重新采样交换流。稳定 GID 在重排、迁移和重启后保持；新增粒子的 ID 生成政策需无冲突且可恢复。

### 5.2 区分三种复现性

- 同一构建、配置、种子和执行模式：要求确定性重放。
- 粒子存储重排、交易方向交换：先要求成对随机符号保持预期对称，再检查整体分布不依赖无物理意义的标签。
- 不同线程/MPI 数：先要求统计等价；未实现稳定归约和事件顺序前不承诺逐位一致。

### 5.3 原地交易的顺序偏差

以现有顺序作为参考，增加倒序和按独立子流打乱的诊断版本。先在同一粒子位置图上隔离交换，再做动态位置测试。比较 dt、dt/2、dt/4 下的分布差异及其置信区间。

不要直接换成同步 dw 累加：多个邻居同时扣款会再次造成超额支付。若必须换更新方案，优先评估互不共享端点的交易批次，并完整复验生成过程。

验收：不同 seed 确实改变交换流；同 seed 可复现；重排不会改变单对随机定义；有限步长顺序误差低于提前冻结的数值容差，否则继续缩小步长或更换更新法。

## 6. WP3：运动积分器与实际温控

### 6.1 修复明确错误

修复 `langevin_integrator.cpp` 的 OpenMP 无噪声分支，使 friction>0 时两半步均包含阻尼。以无力单粒子的动量衰减、无摩擦自由运动为最小回归；检查 OpenMP 开关下数学行为一致。

### 6.2 记录所有稳定化操作

审计 main.cpp 中所有速度缩放路径，不能只处理主循环一处。为每种操作增加触发次数、受影响动能、最大修正幅度和对应时刻。社会力的成对/总力截断也单独记录；截断后的力与所报告势能是否一致必须披露。

当前 social_strength=0，因此社会力截断不能直接作为当前 E1/E2 失效证据；它是恢复完整模型前的验证项。

### 6.3 建立参考运动测试

拟定 `V2-INTEGRATOR-C4`：无外场的动量方差与短时位移统计、谐和势中的位置/动量统计、光滑非平坦场、最粗糙的 shuffled 场。逐步长比较，而非只看运行不崩溃。

首选目标是一个定义清楚的 Langevin 离散方案；若采用新的积分器，先写明更新公式，再验证。现有温控可以保留为 legacy 模式用于对照，不与新模式混用。

若移除温控后发散，检查步长、地形梯度尺度、插值及力的一致性；不得重新加一个未记录的截断后宣布解决。

验收：解析或数值参考的误差随步长降低；确认性模式不发生未声明的速度修正；所有修改均有新版本标识。

## 7. WP4：非退化景观数值校准

### 7.1 保留平坦测试，但限制职责

平坦场仍用于守恒、自由运动和隔离交换，不用于校准资源—密度相关的景观效应误差。常数向量的相关应标记 undefined/degenerate，不能把回退零值当成真实零误差。

### 7.2 增加校准场景

拟定 `V3-LANDSCAPE-NUMERICS-C4`：平滑非平坦场、clustered 场和 shuffled 场；小规模及代表性高密度条件。每场景至少三个步长，固定物理总时长、观测间隔和稳态窗口物理长度。

若使用相同随机路径做强收敛测试，需要一致构造细粗 Brownian 增量；相同 seed 并不自动等于相同路径。主结论采用重复样本的弱收敛/分布误差检查，并报告 Monte Carlo 不确定性。

分辨率必须分成两类：同一连续场的数值离散加密，以及重新生成像素尺度随机场。后者改变物理粗糙度，不应称为单纯网格收敛。记录资源直方图、自相关长度、梯度分布、总量和插值规则。

### 7.3 分开冻结两种界限

`numerical_tolerance` 表示离散化误差包络；`minimum_relevant_effect` 表示研究上值得解释的效应。后者若没有实质依据，就明确仅检验“数值上可分辨”，不称社会科学实质意义。

在查看新确认性 clustered-minus-shuffled 效应前冻结这两个界限。样本量不足以可靠估计误差时补校准，不使用 1e-6 下限替代证据。

验收：每个确认性指标有非退化校准、至少三级步长证据和不确定性说明；尺度变化与数值分辨率变化被分开。

## 8. WP5：稳态判据重建

### 8.1 哪个指标声称稳态，就检查哪个指标

空间指标至少包括 Spearman、Moran's I、占据熵；财富至少包括 Gini、方差、均值/总量、分位数和零财富质量。尾部样本不足时只报告分位数，不强拟合尾指数。

标量检查仍不能证明完整联合分布平稳。因此还应比较相邻窗口的密度图和财富经验分布；结论写为“在指定观测量和时间尺度上未检出漂移”。

### 8.2 观测与停止规则

当前锁定 24 个快照、ESS>=4，可用于粗筛，不能自动当成充分混合。先用 pilot 估计各指标相关时间，再冻结采样间隔、窗口长度和目标精度。窗口前后半段、多个相邻窗口都检查漂移；用保留时间相关性的误差估计。

候选延长规则为 T→2T→4T，但最长时间和允许延长次数必须在新确认性执行前冻结且受预算约束。达到上限仍不稳定就 inconclusive，不删除失败指标。保留每个失败 run，不能只汇总通过者。

绝对漂移容差可解决近零均值归一化退化，但要依据数值精度与指标用途提前冻结；同时报告绝对漂移、相对漂移和区间，不能只显示布尔值。

### 8.3 初值敏感性

在相同参数下比较小扰动财富、较大财富异质性以及不同空间初值。若多个长期分布依赖初值，则报告多稳态或混合未充分，不预设唯一稳态。equal-state 吸收与非平凡稳态并存时尤其如此。

验收：Moran's I 不再因慢而免检；Gini 不能替代方差；分析判据变化有日志，变化后的数据只作探索或用新独立数据确认。

## 9. WP6：重构确认性研究设计

### 9.1 E1：保留主要问题

继续比较总资源、边际分布、人口与初值匹配的 clustered / shuffled 景观。使用通过 WP1–WP5 的核心、新种子及锁定分析代码。每个 seed 的时间窗口摘要是重复单位，不把快照当独立样本。

主指标、共主指标及多重比较家族提前列明；同时报告效应、区间、数值误差和失败率。稳态失败不通过选择性剔除修复。

### 9.2 E2：先明确能回答的问题

空间部分定位为通道隔离验证：生产开关不应改变没有反馈路径的位置过程。财富部分研究移动和生产—衰减组合如何改变财富结构。

若确需分离纯生产与衰减，另行写出固定背景源、固定 sink 等条件下的可比较设计，先检查各 cell 是否存在可比较的长期状态。不能为了凑齐 2×2 而把不同过程都叫同一个因子。

若要增加“财富影响迁移”，留作后续研究问题，需要微观行为依据、额外参数校准和新因果图；不混入本次可信度修复。

### 9.3 E3：拆开规模与密度

固定域增加 N 同时改变人口和密度，不能单独归因于系统规模。分别设计：固定密度扩大域/人口，以及固定域增加人口。明确景观相关长度、作用半径及资源总量如何缩放。

先在小矩阵验证，确认基础效应和稳态成立再放大。旧保留景观若已用于调整参数，不能继续声称未见数据。

验收：新的 parameter lock 包含模型版本、分析哈希、随机流策略、稳态规则、样本量依据、失败处理和预算；不继承旧 supported 标签。

## 10. WP7：执行模式与工程完整性

### 10.1 邻域覆盖

main.cpp 的 cell 大小目前只取 interaction_range 和 density_radius 的最大值，而交换另有 exchange_cutoff。检查所有模块实际半径：若可超过 cell 大小，固定 3×3 搜索可能漏邻居。使用小粒子集合的暴力枚举作为 oracle，验证边界、不同半径和完全重叠位置的政策。

### 10.2 MPI

检查 halo 交换是否真的接入每步力、交换及密度计算，而不只存在接口；核对跨 rank 成对交易的单次执行和守恒。审计全局指标是否正确 gather/reduce。验收前单 rank 是确认性参考模式，多 rank 不用于扩大科学结论。

### 10.3 Checkpoint

当前接口主要保存粒子与步数，需完整审计 RNG、配置恢复、人口/瘟疫内部状态和累计诊断。做连续运行与中途保存恢复的对照；同配置单 rank 要求轨迹可恢复，变更 rank 的能力另行定义统计验收。

### 10.4 配置与完整模型

检查非法 dt、负温度、零更新间隔、未知键和缺失地形是否 fail fast。特别检查“先缓存 interval，后修正 cfg”的路径。完整模型还需死亡粒子、compact 后索引缓存、继承和资源收支验证；未使用模块的失败单独登记，不扩大当前受控实验的验证声明。

验收：发布明确的支持矩阵，列出 serial/OpenMP/MPI/restart 各模式是否通过以及适用配置。

## 11. WP8：性能优化

先记录每步真实邻居对数量及 dynamics/exchange/analysis/I/O 分时，区分高密度物理上更多交互与不必要的程序开销。空间 cell list 并不保证聚集状态下始终 O(N)。

优先处理重复扫描、分配、输出频率和只读向量化；交换并行化最后做。GPU 迁移需要保持交易过程或明确声明近似，并与冻结 CPU 参考比较，不能以吞吐更高替代正确性。

性能验收同时报告误差、峰值内存和 wall time。没有实测前不承诺加速倍数，也不直接沿用旧 E3 并发数。

## 12. 实施阶段、产物与预算控制

| 阶段 | 工作 | 产物 | 进入下一阶段条件 |
|---|---|---|---|
| A | WP0 因果与证据冻结 | 问题台账、基线清单、主张处置表 | 各结论归属明确 |
| B | WP1–WP3 核心修复 | 代码、回归记录、实际模型规范 | 守恒/边界/运动/随机性通过 |
| C | WP4–WP5 校准 | 非退化误差表、稳态 pilot、停止规则 | 关键指标可稳定测量 |
| D | WP6 设计冻结 | 新 plan、参数锁和分析哈希 | preflight 与代码对齐审查通过 |
| E | 新 E1/E2 小规模确认 | 原始摘要、效应和失败清单 | 基础结论可判定 |
| F | E3 及 WP8 | 稳健性与性能报告 | 预算允许且无未解决 P0 |

先以少量 umi 运行实测 `秒/步、邻居对/步、内存、输出体积`，再用运行数×步数×实测耗时估算 CPU-hours，并为长松弛预留明确上限。统计样本量由 pilot 方差、目标区间精度和多重比较要求确定，不照搬旧 seed 数。

所有数值实验、调试、冒烟测试仅在 umi；orchestrator 仅在 zeus。本地只编辑、静态检查和查看回传结果。所有文件保持在项目根目录内，重产物进入各实验 workspace。跨设备研究产物走 git，运行态不同步。

提交前完成代码对齐与 preflight，结束后 jobctl reconcile；若发现旧执行方式无法提供有效句柄和真实退出记录，应补齐新的执行链，不从 pass=true 反推真实执行成功。投稿前 audit，但 audit 不替代科学验证。

文档和小结果按研究事件提交并 push umi；新的确认性结果属于里程碑，依项目规则同步 github。不得覆盖旧实验记录、强推或自动扩大 CPU/GPU 预算。

## 13. 结果与诊断字段建议

每个新实验保留以下可追溯字段，具体 schema 在实施时与 foundation 对齐：

- source_commit、model_version、analysis_commit、config_sha256、parameter_lock_sha256。
- seed、随机子流版本、线程数/rank 数、构建选项和重启来源。
- 计划/完成物理时长、步长、快照间隔、稳态窗口与延长历史。
- wealth_balance_error、minimum_wealth、zero_wealth_fraction、clamp_count、active_pair_count。
- thermostat_trigger_count、force_cap_count、各模式修正幅度。
- 各指标漂移、ESS/不确定性、稳态判定与明确失败原因。
- outcome：supported / contradicted / inconclusive，以及对应证据边界。

总体 pass 拆成执行完整性、数值正确性、稳态充分性、效应判定四层，避免一个绿色状态掩盖其他失败。
