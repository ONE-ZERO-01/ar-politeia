# E2-C4 可用 seed 池的窗口决策

**状态：待定夺。** 本文只给出判据、候选与建议，**不替 E2-C4 lock 定值**。窗口的最终取值应与
样本量 R 一同写入 E2-C4 的锁定契约，理由见 §5。

## 1. 为什么这是阻塞项，而不只是正式运行的前置

[e2-cycle4-channel-design.md](e2-cycle4-channel-design.md) §8 已定：先跑**非证据 pilot**
（5 单元 × 8 seeds = 40 runs）估计各对比方差，再据此冻结 R。pilot 与正式运行都要求
**seeds 全新且互斥**，所以：

- pilot 自身就需要 **8 个全新 seed**（去重后 5 个单元共用同一批 seed，见 §8）；
- 正式运行需要 **R 个**全新 seed；
- 两者都必须落在同一个"无历史占用"的窗口内，否则 `seeds-audit` 会在提交前报未登记复用。

因此窗口不是"等 R 定了再说"的事，**它是 V1G 结束后第一个要提交的 job 的前置**。

## 2. repo 已占用的边界（实测，2026-09-17）

`seeds-audit` 的台账：**28 个 job、211 个不同 seed，范围 101–12241**。
即 **任何 > 12241 的窗口都必然不含历史 seed**，这是选窗口时可用的最强简化。

## 3. pilot 与正式的 seed 是否应共用：不共用（有先例）

若两者共用同一批 seed，pilot→正式之间就构成一次"已登记复用"，需要额外的理由与登记条目；
更麻烦的是，正式运行会**重执行** pilot 已跑过的 seed，于是"用 pilot 估出的方差"与"正式运行的
实际方差"来自同一批 seed，正式运行不再是该方差估计的独立确认。

仓库已有先例，方向明确：

| job | 性质 | 其 seed | 目标实验的 seed | 相交 |
|---|---|---|---|---|
| `V1P-RUNTIME-PILOT-C4` | 计时 pilot | `6007` | V1：`6101…6503` | **空** |
| `V1D-STATIONARITY-DIAGNOSTIC-C4` | 平稳性诊断 | 重分析，未消耗 seed | V1：`6101…6503` | **空** |

即本项目的 pilot/诊断一律跑在**自己独立的 seed** 上。故建议 pilot 与正式各用独立子集，
两批都全新、彼此不相交。

## 4. 窗口的选取判据

1. **不含任何历史 seed**——窗口下界须 > 12241（§2）。
2. **宽度须远小于最小 rank 派生偏移**。`politeia/src/main.cpp` 用
   `random_seed + rank × 1000003`、`+ rank × 999983`、`+ rank` 作基点派生，故多 rank 跑时
   两个 seed 若相差恰为 `999983` 的整数倍，会在相邻 rank 上撞到同一随机流。E2-C4 声明
   `nprocs=1`（rank 恒 0），该别名不能发生；但**窗口宽度做成远小于 999983**（下文候选最大宽度
   1700）便使这条约束在将来放宽为多 rank 时仍然自动成立。
3. **素数个数足够 pilot + 正式 + 余量**。至少 8 + R；若按 §8 的 R 上取 2 的幂至 32，则需 40；
   为 R 可能取到 64 留余量则需 72。
4. **取值方式确定**：`seeds-audit --propose N` 取窗口内**最小的 N 个未用素数**，顺序确定、
   可复核，不引入新的随机选择。
5. **不与将来可能的窗口重叠**：若 pilot 与正式分窗冻结，两个窗口必须不相交；`seeds-audit`
   会把任何未登记的重叠报错，但事先分开更省事。

## 5. 候选（实测未用素数计数）

| 窗口 | 宽度 | 未用素数 | 够 pilot(8) | 够 pilot+正式(8+32) | 够留到 R=64(8+64) |
|---|---|---|---|---|---|
| `12300–12500` | 200 | 22 | 是 | 否 | 否 |
| `12300–12700` | 400 | 46 | 是 | 是 | 否 |
| **`12300–13000`** | **700** | **77** | **是** | **是** | **是** |
| `12300–13400` | 1100 | 119 | 是 | 是 | 是 |
| `12300–14000` | 1700 | 182 | 是 | 是 | 是 |

示例：`--pool-min 12300 --pool-max 13000 --propose 40` 给出
`12301, 12323, 12329, 12343, 12347, 12373, 12377, 12379, … 12613, 12619, 12637, 12641`
（最大 − 最小 = 340，远小于 999983）。

**建议 `12300–13000`**：77 个未用素数足以覆盖 pilot 与直至 R=64 的正式运行（72），余量 5；
宽度 700 使判据 2 稳固成立；且不做无谓的过大承诺。

一个**更保守的替代**是分两次冻结：现在只为 pilot 冻结一个窄窗口（如 `12300–12500`，22 个素数），
正式运行的窗口等 R 定了再冻结。好处是不提前承诺；代价是将来要再走一次冻结流程，且两个窗口
必须人工保证不相交。

## 6. 不在此决定的理由

窗口会进入 E2-C4 的锁定契约，与 R、单元数、阈值同属**预注册参数**。R 尚未由 pilot 定出，
此时把窗口一并定死，等于在一个尚未定的设计上多加一处承诺；而若将来 R 超出窗口容量，
就需要新的 lock 版本。故本文只给判据与候选，**取值由研究者在冻结 E2-C4 lock 时决定**，
并应与 R 同批写入。

窗口一旦写入 lock，即受 `amendment_policy` 约束：任何随结果而动的调整都需要新的 lock 版本
与新的研究 cycle。

## 7. 冻结后如何复核

```bash
python3 research/src/experiments/prepare_cycle4_confirmation.py seeds-audit \
  --pool-min <下界> --pool-max <上界> --propose <需要个数>
```

输出给出未用素数计数与确定性的 seed 提议；`research/jobs/` 出现新 job 后重跑，若新 job 用了
窗口内 seed，`--propose` 会自动跳过它们，而任何未登记的跨 job 复用会让审计报错。
