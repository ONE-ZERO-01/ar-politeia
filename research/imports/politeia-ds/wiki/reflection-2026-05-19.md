## 二、深度反思

### 2.1 KE 发散的根因分析 — 物理尺度不匹配

**核心洞察**: 问题不是"力太大"，而是**力的尺度与热力学尺度严重不匹配**。

定量分析：
- 热速度: `v_th = sqrt(T/m) = sqrt(0.3) = 0.55`
- 旧力上限 `F_TOTAL_MAX=200`: 单步动量变化 `dp = F*dt = 200*0.01 = 2.0`
- dp/v_th = **3.6** — 单步力的作用是热涨落的 3.6 倍！

这意味着在高密度区域，每一步都有大量粒子被"踢"出热平衡。Berendsen 恒温器
每 10 步才运行一次，来不及恢复平衡。结果是持续的净正功注入。

**修复后的尺度匹配**:
- 新力上限 `F_TOTAL_MAX=50`: `dp = 50*0.01 = 0.5`
- dp/v_th = **0.91** — 接近但不超过热涨落

**深层教训**: 在 Langevin 动力学中，任何力参数都应该与 `v_thermal / dt` 比较。
如果 `F_max * dt >> v_thermal`，系统必然热力学不稳定。这是一个**维度分析**问题，
应该在设计阶段就能发现。

### 2.2 恒温器设计的失误 — 三个独立错误的叠加

旧恒温器代码中有三个独立的错误：

| 错误 | 影响 | 严重程度 |
|------|------|----------|
| 目标 KE = 0.5*N*T (应为 N*T for 2D) | 目标偏低 50% | 中 |
| 每 10 步才运行 | 允许 10 步的无控制发散 | 高 |
| 瞬时重置 (无梯度) | 能量剧烈震荡 | 低 |

单独任何一个错误可能不致命，但三者叠加导致恒温器完全无法控制力注入的能量。
这是**错误积累**的典型案例——每个单独看起来都是"小问题"或"近似"，
但组合在一起产生灾难性后果。

**教训**: 在物理模拟中，"近似"不是无害的。每个近似都应该有明确的有效范围
和失效条件。当系统演化进入新的参数区间（如深层级、高密度），近似可能突然失效。

### 2.3 工具链的脆弱性 — 比代码 bug 更耗时

**问题**: 本次会话中遇到的工具链问题比代码 bug 消耗了更多时间：

| 工具问题 | 消耗时间 | 对比：代码修复时间 |
|----------|----------|-------------------|
| Shell inline 模式无输出 | ~1h (多次重试) | KE 修复: 30 min |
| 发现后台三重执行 | ~30 min | 恒温器重写: 20 min |
| NFS 锁 + CMake 竞争 | ~30 min | 力上限调整: 5 min |
| 进程清理 (杀多余实例) | ~20 min | — |

**核心反思**: 代码本身的修改非常简单（改几个常量 + 重写 15 行恒温器），
真正的困难在于**执行环境的不可靠性**。

**Shell 三重执行 bug 的影响**:
1. 构建时 3 个 make 进程竞争写同一文件 → 构建失败
2. 运行时 3 个模拟进程竞争 CPU/内存 → 浪费资源
3. 日志被 3 个进程混合写入 → 输出不可读
4. 需要手动清理多余进程

**教训**:
- 后台命令必须使用 `flock -xn` 确保单实例
- 关键操作应写成脚本，脚本内自带去重逻辑
- 日志文件应使用 PID 或时间戳区分

## 六、方法论总结

经过两天的调试，形成以下工程方法论：

### 6.1 "维度分析先行"原则

在设置任何力/速度/能量参数时，先做维度分析：
```
F_max * dt ≤ sqrt(k_B * T / m)    # 力上限约束
τ_thermostat ≤ dt * 10             # 恒温器耦合约束  
dt ≤ σ / (10 * v_max)              # CFL-like 稳定性
```

### 6.2 "快速验证流水线"

```
新代码/新参数 → 快速验证 (10K×5K, 1h) → 通过? → 全量运行 (100K×20K, 18h)
                     ↓ 失败
                  修复 → 重试
```

### 6.3 "单实例强制"

```bash
# 任何后台命令都用这个模式
exec 9>/tmp/lockfile && flock -xn 9 || exit 0
# ... actual command ...
```

### 6.4 "日志隔离"

```bash
# 使用 PID + 时间戳命名日志
LOGFILE="run_${VERSION}_$(date +%Y%m%d_%H%M)_$$.log"
```
