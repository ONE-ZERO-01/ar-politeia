## 二、关键问题分析

### 问题 1 (Critical): 层级深度异常 — H=209 不合理

**现象**: 最大政体的层级链深度达到 209 层。即最深处的普通成员到帝国领袖之间有 209 级上下级关系。

**历史最大帝国的层级对比**:
- 罗马帝国: ~5-7 级（皇帝→行省总督→城市官员→地方长官→百夫长→基层）
- 中华帝国: ~7-9 级（皇帝→中央六部→省→府→县→乡→里→甲）
- 现代企业: ~8-12 级（CEO→SVP→VP→Director→Manager→Staff）

**根因分析**:

```
form_attachments() [每 compact_interval 步运行]:
  for each root particle i:
    dominator = max_inflow_neighbor(i)
    if dominator is alive:
      superior(i) = dominator.global_id   // ← 不检查 dominator 的深度
      
问题: dominator 可能已经在链的第 150 层
→ i 变成第 151 层
→ 下次 compact_interval, i 的邻居又附着到 i
→ 链无限增长
```

代码定位：
- `src/interaction/loyalty.cpp` line 15-47: `form_attachments()` — 无深度限制
- `src/analysis/polity.cpp` line 84: `MAX_CHAIN = 200` — 深度计算截断
- `src/interaction/loyalty.cpp` line 190: `MAX_DEPTH = 100` — 权力传导截断

**影响**:
1. **物理不真实**: 人类社会不可能维持 200 级管理链条
2. **权力传导失效**: `compute_effective_power()` 只追踪 100 层，超深链中底层财富无法传导到顶层
3. **忠诚度衰减**: 沿 200 级链传导的忠诚度积 L^200 → 0，实际失去控制力
4. **计算浪费**: 深链遍历消耗额外 CPU

**修复方案**: 在 `form_attachments()` 中添加深度限制 (MAX_HIERARCHY_DEPTH = 10)。

## 三、深度反思

### 3.1 层级深度问题的本质 — 算法缺陷还是参数问题？

这是**算法缺陷**。`form_attachments()` 的设计假设是每个 compact_interval 只添加少量新链接，链条自然不会太深。但在 80K 粒子的密集场景中：

- 每次 compact_interval 形成数百个新附着
- 附着目标不考虑已有链深度
- 征服同样不限深度
- 结果是链条不断增长，最终达到数百层

**类比**: 这就像一个公司没有管理跨度限制，允许 200 级管理层级——不仅不现实，而且会导致信息传递失真。

**修复原则**: 引入 `MAX_HIERARCHY_DEPTH` (建议 8-12)，在附着和征服时检查深度。超深链条应自然断裂（叛乱）而非继续增长。

### 3.2 人口动态的科学意义

人口从 100K 下降到 75K 并不一定是 bug。这可能反映了：

1. **承载力调整**: 初始人口超过环境承载力，自然回落
2. **人口转型**: 类似现实中的人口转型理论（高出生高死亡 → 低出生低死亡）
3. **Gompertz 效应**: 初始年龄分布的衰老效应

但需要验证的是：人口是否会**稳定**在某个值，还是会**持续下降到零**。关键信号是儿童比例 (frac_children) 是否持续回升。

### 3.3 与快速验证的对比

| 指标 | 快速验证 (10K×5K) | 全量运行 (100K×5K) | 差异原因 |
|------|-------------------|-------------------|----------|
| 初始密度 | 1/单位面积 | 10/单位面积 | 全量密度 10× |
| 人口趋势 | 增长 (10K→55K) | 下降 (100K→75K) | 承载力限制 |
| H (层级深度) | 11 | **209** | 更多粒子 = 更长链 |
| 帝国数 | 0 | **3** | 更大规模 = 帝国涌现 |
| Gini | 0.711 | 0.769 | 密集竞争加剧不平等 |

## 五、方法论更新

### 新增原则: "结构性限制优于自由增长"

层级深度问题教训：自然系统有内在的结构性约束（管理跨度、信息衰减、叛乱阈值）。模型中缺少这些约束会导致非物理的自由增长。在设计涌现系统时，需要明确识别并实施现实世界中的结构性限制。

### 确认原则: "快速验证流水线"价值

快速验证 (10K×5K) 正确预测了 KE 稳定性，但由于规模差异未能暴露层级深度问题。教训：快速验证适合检测物理 bug，但不适合检测规模相关的涌现问题。需要同时维护多尺度验证。
